# fixtures

Real payloads captured from live `claude` sessions.
They are recordings, not hand-written mocks.

| Path | What it is |
|---|---|
| `tailscale/status-six-nodes.json` | **A tailnet as `tailscale status --json` reports it**, recorded from Tailscale 1.104.2 on a computer with five peers: one user, nothing tagged or shared in, two peers offline. Its `User` map holds this computer's user, whose login is replaced by `owner@example.com`. Only the fields CodeConnect reads are kept, and every name, address, user id, node key and stable node id (`ID`) is replaced. `mac/protocol/src/tailnet.rs` reads it, and its tests make the other-user and tagged cases by editing one field of it. |
| `wire/peers.json` | **The `peers` frames, as the daemon emits them**, not hand-written: for the recorded tailnet above, for Tailscale installed but not running, and for no Tailscale. `mac/protocol/src/tailnet.rs` re-derives it and requires the same JSON, and its ignored generator rewrites the file. It is the fixture for the apps' decoders of this frame, which keep a copy under `ios/`. |
| `host/messages.jsonl` (23) | **The lines between `ccd` and a Claude run's agent host, as this build emits them**, not hand-written. Each line is `{"dir": "to_host" \| "from_host" \| "host_json", "message": …}`, and every message of both directions has at least one line, plus `host.json`. `mac/protocol/src/host.rs` re-derives it and requires the same JSON, decodes and re-encodes every line, and its ignored generator rewrites the file. The agent host reads it by path: `mac/agent-host/test/protocol.test.ts` makes each line a typed constant that Bun's type checker must accept against `src/protocol.ts`, and `test/host.test.ts` takes `host.json`'s version and the `start` line from it. |
| `wire/folder-trust-wire.json` | **The folder question ("trust this folder?") on the wire, as the daemon emits it**, not hand-written: a start without an answer and the `needs_trust` it gets, the start that answers, and the `list_folder_trust`, `set_folder_trust` and `forget_folder_trust` frames with the `folder_trust` list they get. The folder's path and the answer's time are fixed values. `mac/ccd/src/start_session.rs` re-derives it through the start path and the store and requires the same JSON, and its ignored generator rewrites the file. It is the fixture for the apps' readers and writers of these frames, which keep a copy under `ios/`. |
| `wire/qr-link.txt` | **The pairing link a QR carries, as the daemon emits it**: one line, then a newline. `mac/protocol/src/pairing.rs` re-derives it and requires the same bytes, and its ignored generator rewrites the file. It is the fixture for the apps' and the web page's readers of the link, and the apps keep a copy under `ios/`. |
| `appattest/attestation-object.b64` | Apple's own published App Attest attestation object, base64 at 76 columns, 5906 bytes decoded. From the DocC payload behind <https://developer.apple.com/documentation/devicecheck/attestation-object-validation-guide> — the rendered page is a script shell, the JSON carries the object. It is the only genuine Apple chain in existence to test against, and the only thing that catches Apple's P-384-key/SHA-256-signature pairing: a chain minted at test time cannot reproduce it, so a narrowed algorithm list would pass every synthetic test and reject every real device. Its credential certificate was valid for three days in April 2026 and has expired, which is why `mac/push-relay/src/attest.rs` takes the verification time as a parameter and its tests pin a clock inside that window rather than reading the system one. |

Two properties are worth stating explicitly, because both were measured
rather than assumed and both drive the design:

* A Codex `thread/started` is a **global broadcast**: every initialized connection
  receives it, subscribed or not, and it is the ONLY frame about a new thread that a
  connection subscribed elsewhere receives. That is what makes it usable as a switch
  signal and what makes ignoring it fatal.
* `thread/resume` **adds** a subscription rather than replacing one. One connection
  resumed thread A, followed a `/new` to B, resumed B on the same socket, and thereafter
  received both threads' streams. Following a switch therefore costs no reconnect — and
  the per-thread filter is what keeps the two apart.
